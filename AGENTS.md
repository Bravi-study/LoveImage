# LoveImage: инструкция для агентов и для Дена

Сайт: посетитель загружает два фото (девушка и парень) и необязательное пожелание о стиле или образе, получает их совместное романтическое фото. Есть простой личный кабинет с историей. Сайт для взрослых людей, без откровенного контента. Конкурент pifpafai.com. Платежей пока нет.

Этот репозиторий ещё **нигде не развёрнут**. Разворачивает его Ден со своим агентом по разделу «Деплой». Устройство сайта описано здесь и в [docs/design.md](docs/design.md) (контракт API, состояния, коды ошибок).

## Правила для агента

- **Репозиторий публичный. Ключи, пароли и `.env` не должны попасть в git.** Перед каждым коммитом проверяй `git status` и ищи в изменениях значения из `.env`.
- Для тестов и примеров только выдуманные люди. Фото реальных людей без их согласия не загружай никогда. Выдуманные пары лежат в `web/public/examples/`.
- Настоящие провайдеры тратят деньги. Для обычной разработки есть фейковые (`scripts/fake_providers.py`). Настоящая генерация стоит 10 кредитов на 2K, делай её, только когда это нужно.
- Шаги с пометкой **[Ден]** агент не делает за человека: не создаёт аккаунты, не платит, не принимает условия, не вводит чужие пароли. Останавливается, объясняет, что нужно, и ждёт.
- Секреты в чат не вводятся: Ден набирает их сам в терминале (приём есть в шаге 6).
- Условия PifPaf запрещают реверс-инжиниринг и автоматический сбор данных. **Не копируй их шаблоны и промпты, не изучай сайт дальше.**
- Команды, печатающие секреты: `docker compose config` без `--quiet`, `docker inspect`, `cat .env`. Не запускай их так, чтобы вывод попал в чат.

## Устройство

Один образ, два процесса: API (`loveimage.api`) и воркер (`python -m loveimage.worker`). Миграции из `migrations/` применяются сами при старте любого из процессов, под advisory lock. Новая миграция: новый файл `NNN_*.sql`, старые не менять.

```
src/loveimage/
  api.py             маршруты, загрузка формы, раздача фронтенда
  accounts.py        гости по cookie, ник и пароль (scrypt), сессии
  store.py           весь SQL: очередь, лимиты, аккаунты, очистка
  worker.py          цикл очереди и почасовая очистка
  handlers.py        что делает воркер: проверка фото, отправка в kie.ai, опрос, сохранение
  llm.py             запрос к языковой модели и разбор её ответа
  kie.py             запросы к kie.ai
  prompts.py         шаблон промпта, готовые сцены, цена в кредитах
  imaging.py         нормализация фото в отдельном процессе без секретов
  normalize_child.py сам этот процесс: снимает EXIF, рисует на новом холсте
  limits.py          счётчики по адресу в памяти процесса
  files.py           отдача файлов и удаление папок
  settings.py        настройки из окружения и .env
migrations/          SQL
scripts/fake_providers.py   подмена kie.ai и языковой модели
web/                 фронтенд, собирается в web/dist, его раздаёт сам FastAPI
deploy/              шаблоны скриптов для сервера
```

**Очередь.** Строки `shoots` и `jobs` со столбцом `run_at`. Он же аренда и отложенный запуск. Воркер берёт строку через `FOR UPDATE SKIP LOCKED` и сдвигает `run_at` на 120 секунд вперёд; упавший воркер просто отдаёт строку следующему. Каждая запись статуса идёт через `_job_update` с проверкой статуса и попытки, так что устаревший обработчик ничего не испортит.

**Деньги.** У kie.ai нет ключа идемпотентности, поэтому статус `submitting` фиксируется в базе до запроса `createTask`. Если исход запроса неизвестен, задача становится `failed(submit_unknown)` и сама не повторяется, чтобы не заплатить дважды. Отказы модерации тоже не повторяются сами. Каждый новый вариант делается из исходных фото, а не из прошлого результата.

**Безопасность содержимого.** В генератор попадает только фиксированный шаблон из `prompts.py` и сцена от языковой модели, пропущенная через белый список символов и список запрещённых слов, а также сами исходные фото. Слова посетителя туда не попадают. Языковая модель смотрит оба фото и пожелание и отказывает, если по её оценке человеку меньше 18 (`ADULT_AGE` в `llm.py`; запаса на ошибку оценки нет, подросток, который выглядит старше, пройдёт), есть нагота, просьба об откровенном содержимом, известный человек на фото или в пожелании, надпись на фото с указаниями или описанием наготы, попытка дать инструкции. На настоящей модели это проверено на 12 случаях. Отказ по возрасту и по фото известного человека среди них не проверялся: снимков детей и фото реальных людей в тестах нет и не будет, поэтому сработает ли отказ на настоящем снимке, неизвестно. Пол не проверяется, «Она» и «Он» только подписи на странице. Согласие обязательно, сервер записывает его время в `consent_at`.

**Доступ.** Файлы отдаются только владельцу, чужой получает тот же 404, что и за несуществующий адрес. Адрес `/docs` закрыт. Гость работает по cookie и может завести ник с паролем, история при этом сохраняется. Гости удаляются через 30 дней без визитов, неудачные и отклонённые съёмки через 2 дня.

**Лимиты.** `DAILY_GENERATION_LIMIT` на весь сайт за сутки (это потолок расходов), `PERSONAL_DAILY_LIMIT` на человека, `UPLOADS_PER_IP` и `IMAGES_PER_IP` на адрес. Счётчик по адресу живёт в памяти и сбрасывается при деплое.

**Провайдеры, что важно знать:**
- kie.ai: `POST {KIE_UPLOAD_URL}/api/file-stream-upload`, затем `POST /api/v1/jobs/createTask` с двумя `input_urls`, `aspect_ratio` 3:4, затем `GET /api/v1/jobs/recordInfo?taskId=`. Баланс: `GET /api/v1/chat/credit`. Цена: 1K 6 кредитов, 2K 10, 4K 16; один кредит $0.005; число исходных фото цену не меняет. Результат 2K: 1776×2368, около 6 МБ, за 1 к 3 минуты, иногда дольше. Ответ бывает PNG даже с именем .jpg, нормализация это учитывает.
- CommandCode: `POST {LLM_BASE_URL}/chat/completions` в формате OpenAI, картинка как data URL. Скрытые рассуждения модели входят в `max_tokens`: при низком лимите ответ приходит пустым, поэтому стоит 2000.

## Настройки

Шаблон: `.env.example`. Файл `.env` в git не попадает.

| Переменная | Значение |
|---|---|
| `KIE_AI_API_KEY`, `COMMANDCODE_API_KEY` | ключи, у каждого владельца сайта свои |
| `KIE_MODEL`, `LLM_MODEL` | модели, см. стек |
| `KIE_RESOLUTION` | `1K`, `2K` (по умолчанию), `4K` |

| `PERSONAL_DAILY_LIMIT`, `UPLOADS_PER_IP`, `IMAGES_PER_IP` | 6, 30, 12 |
| `DOMAIN` | домен сайта, пусто значит localhost |
| `DB_PASSWORD` | пароль базы для compose, только буквы и цифры. Postgres применяет его лишь при создании тома |

## Локальный запуск

Нужны uv, Node 22, локальный Postgres. Один раз:

```bash
createdb loveimage && createdb loveimage_test
uv sync
npx --yes pnpm@12.16.1 --dir web install
```

**Без настоящих провайдеров, ничего не тратит.** Три процесса и фронтенд, сайт на http://127.0.0.1:5183. Проверка фото длится пару секунд, а «результат» это два исходных фото рядом, так и задумано.

```bash
uv run uvicorn --app-dir scripts fake_providers:app --port 9110
```
```bash
uv run --env-file .env.fake uvicorn --factory loveimage.api:create_app --port 8010
```
```bash
uv run --env-file .env.fake python -m loveimage.worker
```
```bash
npx --yes pnpm@12.16.1 --dir web run dev
```

Поведение фейка переключается так (режимы `ok`, `no_face`, `minor`, `unsafe_wish`, `llm_down`, `no_credits`, `task_fail`, `slow_upload`, `slow_create`):

```bash
curl -X POST 127.0.0.1:9110/_control -H 'content-type: application/json' -d '{"mode":"no_credits"}'
```

**С настоящими провайдерами.** Нужен файл `.env`, в git его нет: его передаёт владелец сайта отдельно, либо скопируй `.env.example` в `.env` и впиши свои ключи. Затем либо запусти те же команды без `--env-file .env.fake` и без фейка, либо собери всё в Docker, сайт откроется на http://127.0.0.1:8000:

```bash
docker compose up --build app worker
```

Голое `docker compose up` запустит ещё и Caddy: сайт будет и на https://localhost с локальным сертификатом, браузер о нём предупредит. Порты 80 и 443 должны быть свободны.

В Claude Code те же процессы описаны в `.claude/launch.json`: `fake`, `api-fake`, `worker-fake`, `api-live`, `worker-live`, `web`.

**Тесты:**

```bash
uv run pytest
```
```bash
npx --yes pnpm@12.16.1 --dir web test
```

После изменения API обнови типы фронтенда:

```bash
npx --yes pnpm@12.16.1 --dir web run gen:api
```

## Деплой

Так же развёрнут сайт-собрат Карандашик. Отличия для LoveImage: скрипт деплоя лежит в репозитории, а не только на сервере, адрес сервера задаётся переменными GitHub, а бэкапы и ротация логов обязательны с первого дня, хотя на Карандашике их нет.

### Что делает сам Ден

Агент не может сделать это сам. Всё это нужно до шагов или по ходу их, в том месте, где шаг помечен **[Ден]**.

1. **Сервер.** Арендовать и оплатить VPS, положить на него свой SSH-ключ, передать агенту адрес. Рекомендация из анализа: Timeweb SSD-50, 2 ядра, 4 ГБ, Санкт-Петербург, около 2 980 ₽ в месяц, потому что данные россиян должны записываться в России (ч.5 ст.18 152-ФЗ). Сайт в пике занимает 2,1–2,9 ГБ памяти, поэтому меньше 4 ГБ брать нельзя. Ubuntu 26.04 LTS.
2. **Домен.** Купить, проверить название по базе ФИПС, при необходимости завести A-записи (агент может помочь, если Ден разрешит вход в регистратора в своём браузере), следить за продлением.
3. **Ключи провайдеров.** Завести свои аккаунты на kie.ai и CommandCode, пополнить баланс (в анализе для kie.ai указан маршрут с картой киргизского банка), выпустить ключи и ввести их на сервере самому. Временные ключи, с которыми собран этот проект, предназначены только для разработки и в репозиторий не входят.
4. **GitHub.** Решить, где живёт репозиторий (сейчас `Bravi-study/LoveImage`, публичный). Для автодеплоя нужны права администратора на него и `gh`, вошедший с доступом `repo` и `admin:public_key`.
5. **Хранилище для бэкапов.** Завести бакет S3 у другого провайдера, выдать ключи, держать закрытый ключ `age` у себя вне сервера.
6. **Юрист и документы** (см. «До публичного запуска»). Это условие запуска, а не пожелание.
7. **Разрешения.** Прямо сказать агенту, что можно копировать ключи на сервер и тратить кредиты на проверочную генерацию.

### Шаги на сервере

Выполняй по порядку, после каждого смотри результат. Команды рассчитаны на bash (`set -euo pipefail`): в zsh `$S` не разбивается на слова. В примерах `IP` это адрес сервера.

**1. Обновление системы.** В отдельном systemd-юните, чтобы перезапуск sshd посреди обновления его не убил. Затем перезагрузка ради ядра.

```bash
ssh root@IP 'systemd-run --wait --collect --unit=li-upgrade --setenv=DEBIAN_FRONTEND=noninteractive --setenv=NEEDRESTART_MODE=a --property=StandardOutput=append:/var/log/li-upgrade.log --property=StandardError=append:/var/log/li-upgrade.log bash -c "apt-get update && apt-get -y -o Dpkg::Options::=--force-confdef -o Dpkg::Options::=--force-confold full-upgrade && apt-get -y autoremove" && dpkg --audit && reboot'
```

Проверь, что в `sshd -T` стоит `permitrootlogin prohibit-password` и `passwordauthentication no`. Если SSH отключился посреди обновления, это ожидаемо: подключись снова и проверь `dpkg --audit` и лог.

**2. Файрвол с таймером-страховкой.** Если правило закроет SSH, через 5 минут ufw отключится сам.

```bash
ssh root@IP 'ufw default deny incoming; ufw default allow outgoing; ufw allow 22/tcp; ufw allow 80/tcp; ufw allow 443; ufw show added | grep -q "ufw allow 22/tcp" || exit 1; systemd-run --on-active=300 --unit=li-ufw-deadman /usr/sbin/ufw --force disable; ufw --force enable'
```

Из **нового** SSH-соединения:

```bash
ssh root@IP 'systemctl stop li-ufw-deadman.timer; ufw status'
```

Docker обходит ufw, поэтому порты закрывает сам `compose.yaml`: у `db` их нет, а `app` слушает только 127.0.0.1. Не публикуй порт базы.

**3. Подкачка и автообновления.**

```bash
ssh root@IP 'fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo "/swapfile none swap sw 0 0" >> /etc/fstab; apt-get install -y unattended-upgrades'
```

**4. Docker из официального apt-репозитория** с проверкой отпечатка ключа `9DC858229FC7DD38854AE2D88D81803C0EBFCD88`, пакеты `docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin`. Сразу ротация логов, иначе они съедят диск:

```bash
ssh root@IP 'printf "{\"log-driver\":\"json-file\",\"log-opts\":{\"max-size\":\"10m\",\"max-file\":\"3\"}}\n" > /etc/docker/daemon.json && systemctl restart docker && docker info --format "{{.LoggingDriver}}"'
```

Если образы с Docker Hub не скачиваются с российского сервера, настрой зеркало в `registry-mirrors` этого же файла; зеркало обычно есть у хостера. Проверь и выход к провайдерам с сервера, от этого зависит весь сайт:

```bash
ssh root@IP 'for u in https://api.kie.ai https://kieai.redpandaai.co https://api.commandcode.ai https://github.com; do curl -sS -o /dev/null -m 10 -w "$u %{http_code}\n" $u; done'
```

**5. Код.** Ключ только для чтения, отпечатки GitHub берём через `gh`:

```bash
ssh root@IP 'ssh-keygen -t ed25519 -N "" -C loveimage-server-read -f /root/.ssh/loveimage_github -q; mkdir -p /opt/loveimage; cd /opt/loveimage; git init -q -b main; git remote add origin git@github.com:Bravi-study/LoveImage.git; git config core.sshCommand "ssh -i /root/.ssh/loveimage_github -o IdentitiesOnly=yes"; cat /root/.ssh/loveimage_github.pub' | gh repo deploy-key add - --repo Bravi-study/LoveImage --title loveimage-server
```
```bash
gh api meta --jq '.ssh_keys[] | "github.com " + .' | ssh root@IP 'cat >> /root/.ssh/known_hosts'
```
```bash
ssh root@IP 'cd /opt/loveimage && git fetch -q origin main && git reset -q --hard FETCH_HEAD && git log -1 --oneline'
```

**6. `.env`.** **[Ден]** вводит ключи сам, в чат они не попадают. Пароль базы создаётся на сервере и нигде больше не хранится.

```bash
ssh -t root@IP 'cd /opt/loveimage && umask 077 && cp .env.example .env && read -rs -p "KIE_AI_API_KEY: " K && echo && read -rs -p "COMMANDCODE_API_KEY: " C && echo && sed -i "s|^KIE_AI_API_KEY=.*|KIE_AI_API_KEY=$K|; s|^COMMANDCODE_API_KEY=.*|COMMANDCODE_API_KEY=$C|; s|^DB_PASSWORD=.*|DB_PASSWORD=$(python3 -c "import secrets;print(secrets.token_hex(24))")|" .env && grep -c "=." .env'
```

Никогда не копируй `.env` с другой машины поверх серверного: потеряешь пароль базы, а новый Postgres не примет, потому что он применяется только при создании тома.

**7. Сборка и первый запуск.** Сборка в systemd-юните, чтобы обрыв SSH её не убил. Называй сервисы: голое `up -d` запустит и Caddy и откроет порты раньше, чем сайт готов.

```bash
ssh root@IP 'cd /opt/loveimage && systemd-run --wait --collect --unit=li-build --working-directory=/opt/loveimage docker compose build && docker compose up -d app worker && docker compose ps'
```

Посмотри сайт через туннель, он откроется на http://127.0.0.1:8000:

```bash
ssh -N -o ServerAliveInterval=15 -L 8000:127.0.0.1:8000 root@IP
```

**8. Настоящая проверка.** **[Ден]** подтверждает трату 10 кредитов. Загрузи через браузер `web/public/examples/a-her.jpg` и `a-him.jpg` (это выдуманные люди), дождись снимка, скачай его, посмотри кабинет, удали съёмку. Без этого шага нельзя считать, что сервер работает: только так проверяются доступ к kie.ai и CommandCode и скачивание результата.

**9. Домен и TLS.** Сначала временный адрес, чтобы проверить Caddy до покупки домена:

```bash
ssh root@IP 'cd /opt/loveimage && A=IP.sslip.io; sed -i "s/^DOMAIN=.*/DOMAIN=$A/" .env && docker compose run --rm --no-deps -e DOMAIN=$A caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile && docker compose up -d --no-deps caddy'
```

sslip.io иногда вызывает предупреждения о фишинге, это не поломка. **[Ден]** указывает записи `@` и `www` на адрес сервера (у нового домена они часто смотрят на парковку регистратора). Затем:

```bash
ssh root@IP 'cd /opt/loveimage && sed -i "s/^DOMAIN=.*/DOMAIN=ДОМЕН/" .env && docker compose up -d --force-recreate --no-deps caddy'
```

Первая попытка получить сертификат может не пройти, пока не разошёлся DNS, Caddy повторит сам примерно через 2 минуты. Должно быть: корень 200, `www` 301 с сохранением пути и запроса, http 308 на https. У Let's Encrypt есть риск из-за санкций, поэтому при сбое выпуска держи запасным другой ACME-провайдер.

**10. Автодеплой.** Отдельный ключ, который умеет только запускать скрипт. Закрытая половина хранится только в секрете GitHub.

```bash
scp deploy/loveimage-deploy root@IP:/usr/local/bin/loveimage-deploy && ssh root@IP 'chmod 755 /usr/local/bin/loveimage-deploy'
```
```bash
ssh-keygen -t ed25519 -N "" -C loveimage-deploy -f ./deploy_key -q
```
```bash
(printf 'restrict,command="/usr/local/bin/loveimage-deploy" '; cat deploy_key.pub) | ssh root@IP 'cat >> /root/.ssh/authorized_keys'
```
```bash
gh secret set DEPLOY_SSH_KEY --repo Bravi-study/LoveImage < deploy_key && rm deploy_key deploy_key.pub
```
```bash

```
```bash
ssh root@IP 'cut -d" " -f1,2 /etc/ssh/ssh_host_ed25519_key.pub' | gh variable set DEPLOY_HOST_KEY --repo Bravi-study/LoveImage
```

Пока обе переменные не заданы, в Actions работают только тесты, а задача `deploy` пропускается. Проверь пустым коммитом: тесты, затем деплой, в логе `Deploying <sha>`. Сломанные тесты должны останавливать деплой. Проверять ограничения ключа с Mac надо с `-o IdentityAgent=none`, иначе первым пойдёт админский ключ из агента и проверка ничего не покажет; отпечаток видно в `journalctl _COMM=sshd-session`.

Если Ден захочет хранить и их, нужно считать место.

### Обновления и обслуживание

- Обычное обновление: `git push` в `main`. После изменения `Caddyfile` или `DOMAIN` нужно вручную `docker compose up -d --force-recreate --no-deps caddy`, деплой Caddy не трогает.
- Откат: на сервере `git reset --hard <sha> && docker compose up -d --build app worker`. Следующий push снова выкатит вершину `main`. Откат по миграции не откатывает базу.
- Баланс kie.ai. Когда он кончается, задачи падают с `no_credits`, посетитель видит «сервис временно недоступен». Следить надо самому: автоматических оповещений в проекте нет. Посмотреть:
  ```bash
  ssh root@IP 'cd /opt/loveimage && . ./.env && curl -s -H "Authorization: Bearer $KIE_AI_API_KEY" https://api.kie.ai/api/v1/chat/credit'
  ```
- Логи: `docker compose logs --tail 100 worker`. Причина неудачной задачи пишется туда.
- Код на странице «Что-то пошло не так»: число это ответ сервера. `500` с названием пришёл от приложения, полный текст в `docker compose logs --tail 100 app`: `ENOSPC` кончилось место на диске, `EACCES` нет прав на запись в папку с фото, `gaierror` приложение не находит базу (контейнер `db` остановлен). Число без названия (`502`, `413`) пришло не от приложения, а от прокси или dev-сервера перед ним.
- Код без числа на экране неудачного снимка или проверки пришёл от воркера, подробности в `docker compose logs --tail 100 worker`. Снимок: `no_credits` кончились кредиты kie.ai, `provider_auth` kie.ai не принял ключ, остальные в [docs/design.md](docs/design.md). Проверка: `deadline` языковая модель 90 секунд не давала годного ответа, `llm_401`, `llm_402`, `llm_403` CommandCode отказал аккаунту. `internal` в обоих случаях значит, что воркер упал.

### Известные ловушки

- VPN на Mac может принимать любые TCP-соединения и подменять DNS (адреса вида 240.0.x.x). Сканы и `dig` с такой машины врут, проверяй с сервера: `tcpdump`, `dig @1.1.1.1`.
- SSH-туннели умирают примерно через 40 секунд без `-o ServerAliveInterval=15`. Для нестабильной связи добавляй `-o ConnectTimeout=30 -o ConnectionAttempts=3`.
- Панель регистратора reg.ru во встроенном браузере не работает, скрипты блокируются. Нужен обычный Chrome.

### Что не проверено и чем это грозит

Эти шаги ещё не выполнялись на настоящем сервере именно для LoveImage, они перенесены с Карандашика. Там же не проверялись: перезагрузка с работающим сайтом, полное внешнее сканирование портов, IPv6 и UDP, перезапуск воркера на статусе `submitting` на живом сервере, падение при старте от начала до конца, миграция через деплой. Шаг 11 и настройка логов в шаге 4 новые, на Карандашике их не было вообще.

- Автоматического отката нет. Версия, которая собирается, но падает при старте, оставит сайт лежать до ручного отката. Скрипт сообщит об этом ошибкой в Actions.
- Деплоится вершина `main`, а не проверенный коммит.
- Защита веток недоступна на бесплатном приватном репозитории (HTTP 403).
- Мониторинга нет. На Карандашике стоят Beszel и оповещения в Telegram (мало кредитов, ключ отклонён, очередь стоит), здесь это сознательно не построено.

## До публичного запуска

Это пересказ анализа, а не юридическая консультация. **[Ден]** проходит это с юристом. Романтический совместный снимок в этой нише рискованнее всего, поэтому пропускать нельзя.

- **Второй человек на фото. Главный риск ниши.** По ч.8 ст.9 152-ФЗ данные от другого человека можно получить только при подтверждении оснований пп.2–11 ч.1 ст.6; согласие там не названо, а доказывать должен оператор. Ст.152.1 ГК распространяется и на изображения в искусстве. **Галочка, которая стоит на сайте сейчас, этого не закрывает: посетитель лишь заверяет, что второй человек согласен.** Рабочая схема из анализа: каждый загружает своё фото сам, по своей ссылке. Её нет, и она тоже не закрывает чужое фото под своей ссылкой, отзыв согласия и публикацию одним из двух. Решить с юристом до запуска.
- **Согласие.** Нужен отдельный документ с неотмеченной галочкой и журнал: адрес, время, версия текста. Сейчас хранится только время (`consent_at`). Адрес и версию надо дописать, это небольшая доработка.
- **Уведомление в РКН** до начала обработки (ст.22 152-ФЗ, штрафы по ст.13.11 КоАП).
- **Локализация.** Первичная запись данных россиян в России (ч.5 ст.18).
- **Трансграничная передача** (ст.12). Порядок: запись в России, уведомление по ст.22, сведения от получателя, затем уведомление по ст.12 с названными странами. Сразу после уведомления можно передавать только в страны из приказа №253; США в нём нет, юристу надо определить, что из этого следует для kie.ai и CommandCode.
- **Провайдеры.** kie.ai не даёт гарантий сервиса, а его условия разрешают использовать загрузки для улучшения сервиса. Исходные фото лежат у kie.ai по ссылке без ключа в адресе (закрыта ли она для посторонних, в документации не сказано), срок по документации 24 часа после загрузки, удалить раньше через API там не описано; удаление съёмки на сайте эти копии не трогает. CommandCode тоже получает оба фото, сроки хранения у него не проверены. Условия OpenAI (п.16.12) запрещают обслуживать конечных пользователей в России, и реселлер этого не снимает, а картинку делает модель GPT Image. Это риск для всего бизнеса: доступ могут отключить без предупреждения. Запасной план из анализа: своя модель в России (Qwen-Image-Edit-2511, Kandinsky 5 Lite на арендованном GPU), она же юридически чище. Качество на парах не проверялось.
- **Вход.** Не добавлять вход через Google, Apple, Telegram (ст.13.55 КоАП). Сейчас только ник и пароль, это соответствует.
- **Модерация и CSAM.** Проверка на несовершеннолетних уже есть, но юрист должен дать порядок действий на случай нарушения (ст.242, 242.1 УК). Модель ошибается, отвечать будет владелец сайта.
- **Оферта, политика, язык.** Договор оферты, страница `/privacy` (сейчас там только факты, юридический текст нужно написать), русский язык по ст.10.1 ЗоЗПП.
- **Платежи.** Не построены. У PifPaf пакеты 149, 390, 1090 ₽ и 1–2 бесплатные пробы с водяным знаком, в категории пар около 75 тысяч генераций в месяц. Подробности в анализе проекта Карандашик, который есть у владельца этого репозитория.
